# Proof-Tree Irresolution

Status: source-backed SPOTCOMP interpretation layer.

SPOTCOMP should be read as a categorical proof engine for cases ordinary
total-function interfaces cannot safely resolve. It does not convert every
input into a total answer, a host exception, or a silent default. It keeps the
unresolved material typed, staged, replayable, and auditable until the active
regime supplies a fixed point, trajectory prefix, obstruction, contradiction,
abstention, or downgrade.

This is not a new subsystem. It is the same process viewed across the whole
proof tree:

`utterance -> articulating -> predicating -> positing -> settling -> TRC/TDP replay`

## 1. Recursion And Bottoming Out

The active tree makes articulating recursive: an articulating instance carries
an utterance and another articulating position. Concrete instances become
finite only because token and claim are non-assembling primitives, and
utterance is their ordered carrier pair.

SPOTCOMP therefore treats external presentation as something to be placed in
this recursion, not as direct evidence. If a handler cannot produce or cite a
typed utterance, the process remains before articulating. If it can, the
utterance opens the aperiodic category rather than forcing a settled answer.

## 2. Stage Preservation

The current active branch records the stage chain as:

`articulating -> aperiodic-articulation-category`

`predicating -> transfinite-predication-category`

`positing -> scott-continuous-posit-category`

`settling -> finite-settlement-algebra`

Irresolution is handled by preserving these boundaries. A value or event may
be meaningful at one regime and invalid at another. A stable aperiodic cell is
not a valid predicating domain merely because it is a valid aperiodic cell. A
bounded finite prefix is not a final settlement merely because it is a valid
finite presentation.

## 3. Partial Functions And Bottom Extensions

The predication fibration uses partial maps between cell coordinates. Cells
outside the support of a predicate-category reindexing are extended by a
declared bottom/default value, and later gauge-twisted work shows that changing
the default is itself a mathematical boundary with obstruction behavior.

For SPOTCOMP, this means partiality must be explicit:

- the support of a partial map must be declared;
- outside-support behavior must cite the chosen bottom/default discipline;
- obstruction or parity failures are evidence, not runtime accidents;
- a host null, thrown exception, or fallback string is not a proof-tree result
  unless admitted as typed boundary evidence.

## 4. Closure, Prefixes, And Apex

Closure is a lax-idempotent 2-monad, and settling is a closure-plus-increment
orbit. The settling apex is the Knaster-Tarski least fixed point when the
regime permits endpoint evidence. When fixed-point evidence is absent, the
system may carry a trajectory prefix, local settling, cohomology audit,
obstruction record, or downgrade.

The important rule is negative:

bounded execution is not settlement.

Fuel exhaustion, timeout, missing witness, unverifiable cohomology, unresolved
recognition, and unsupported regime claims must remain typed non-final states.
They must not be reported as final values.

## 5. TRC/TDP As Executable Proof Tree

TRC/TDP is the on-disk running proof tree. It records:

- schemas as type/proposition/object witnesses;
- logs as trace evidence;
- morphism scripts as executable terms;
- dual filing as subject/predicate anchoring;
- import aliases as stable script and schema identities;
- replay as reconstruction of working state from trace evidence;
- closure-rule execution as the running theory derivation program.

This is why unresolved cases can persist without being lost. A SPOTCOMP
implementation can keep an unresolved input typed and replayable instead of
collapsing it to an exception or an untracked default.

## 6. I/O And Outside Systems

Outside systems, including LLMs, supply presentations. They do not supply
settlement unless they are themselves modeled players whose outputs are
admitted through the same proof-tree boundary.

An LLM completion can propose a claim. It cannot by itself certify:

- articulating category generation;
- typed predicating placement;
- positing naturality;
- closure-rule firing;
- fixed-point settlement;
- modeled-player strategy equivalence;
- standards conformance of the transported object.

Each of those claims belongs to the relevant proof-tree stage.

## 7. Standards Consequence

IETF/RFC conformance is feasible because the proof tree says what object is
being serialized, signed, transported, rejected, or reported. Without that
object boundary, a standards check can only validate bytes or protocol shape.

For SPOTCOMP:

- JSON and canonicalization constrain finite carrier identity;
- signatures authenticate carrier/sender claims, not settlement;
- HTTP and problem-details profiles report handler outcomes without changing
  stage placement;
- media types bind derived objects only after their proof-tree position is
  declared.

The standards layer is therefore downstream of categorical placement, not a
substitute for it.

## 8. Declaration Probe

[schema/proof-tree-irresolution-profile.schema.json](./schema/proof-tree-irresolution-profile.schema.json),
[examples/proof-tree-irresolution-profile.json](./examples/proof-tree-irresolution-profile.json),
and [src/proof-tree-irresolution-profile.mjs](./src/proof-tree-irresolution-profile.mjs)
define a declaration-level probe for this surface.

The probe checks that profiles declare:

- token/claim/utterance as finite recursion base;
- stage/regime preservation from articulating through settling;
- partial-map support and bottom/default discipline;
- fixed-point, prefix, obstruction, and downgrade boundaries;
- TRC/TDP replay as executable proof-tree evidence;
- outside-system and LLM output as presentations until admitted;
- standards conformance after object-boundary derivation.

The probe does not prove the active tree, compute closure, inspect live
catalogs, validate LLM behavior, verify signatures, or decide cohomology.
