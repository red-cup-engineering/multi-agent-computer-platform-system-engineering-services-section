**Engineering records for computer platforms that host, compose, and
coordinate multiple agents.** This repository is a specialization of the
[Agent Computer Platform System Engineering Section](https://github.com/red-cup-engineering/agent-computer-platform-system-engineering-services-section).
It holds source material and historical application lineages rather than
a distributable agent host.

The repository's `package.json` is a grouping manifest. It has no
root-level command, public application export, or verification script.
Cloning it is **not** an installation of an agent platform.

## What can be explored here

- [SPOTCOMP written material](apps/spotcomp/content/text): retained
  material concerning its Subject–Predicate–Object traces and Modeled
  Players research.
- [SPOTCOMP historical implementations](apps/spotcomp/lib/legacy):
  dated snapshots and prototypes, kept as historical source evidence.
- [Platform system material](content/text) and [legacy holdings](lib/legacy)
  for the wider specialization.

An older README described `apps/spotcomp` as a working computer.
In the current tracked tree that path contains written material and
`lib/legacy`, **not** its own runnable package, exported module, or live
server. The name identifies a research and engineering lineage; it is
not a claim of an available, maintained runtime.

## Where running platforms live

The sibling [Multi-Agent Computer Platform Engineering Section](https://github.com/red-cup-engineering/multi-agent-computer-platform-engineering-services-section)
indexes the actual platform projects (including FeltOS and MetroPlat).
Most of those implementation repositories are private and require
separate source access; the public composition is not a turnkey
distribution. Start with each accessible source owner's exports,
tests, and operating evidence, not a historical app name.

For the multi-agent *computer-system* behavior rather than its
hosting platform, see
[Multi-Agent Computer System Engineering](https://github.com/red-cup-engineering/multi-agent-computer-system-engineering-services-section).

## Status and boundaries

This repository establishes historical and organizational source custody.
It does **not** establish a deployed platform, independent conformance,
security posture, or the availability of any SPOTCOMP application.
Those claims require a maintained implementation, its exact tests, and
a separately verified operator/receiver.
